## 1. 작업 흐름

### 1-1. 탐색기 우클릭 메뉴가 사라진 원인 규명

**배경/요구**: 사용자가 "Genspark Speakly 가 왜 컨텍스트 메뉴에 안 나타나지?" 로 시작.
확인해 보니 그 앱만이 아니라 **모든 `.lnk` 에서 항목이 사라진** 상태였다.
사용자 체감은 "윈도우 업데이트 후부터" 였다.

**처리**: 업데이트가 원인이 아니었다. 시간순으로 재구성:

| 시점 | 사건 |
|---|---|
| 8/18 | 셸 확장을 **개발 폴더** `Etc Project\Electron Project\Blueming Menu\native\shell-ext\dist` 기준으로 등록 |
| 8/27 10:08 | 상위 폴더 3개를 공백 없는 이름으로 변경 → 등록 경로가 **존재하지 않게 됨** |
| 8/27~8/30 | 탐색기가 이미 로드한 DLL 을 물고 있어 **멀쩡히 동작** |
| 8/31 | 윈도우 업데이트(KB5120998/KB5120997) 재부팅 → 탐색기 새로 뜨며 DLL 로드 실패 → 메뉴 소멸 |

**결정적 증거 3가지**:
- `Get-AppxPackage BluemingMenu.ShellExt` 의 `InstallLocation` 이 **비어 있음**
- `explorer.exe` 에 `blueming_shell_ext.dll` **미로드** (반디집·PowerToys·VS Code 는 정상 로드)
- 다른 MSIX 컨텍스트 메뉴 앱들은 전부 `Status: Ok` + 경로 정상

**결과**: `scripts/setup-installed.ps1` 로 설치 루트 기준 재등록 + 탐색기 재시작 → 복구 확인.
파이프 질의(`QUERY`)로 앱 응답 경로도 검증(`ABSENT` 정상 응답).

### 1-2. 폴더 오버레이가 패널을 닫아도 남던 버그

**배경/요구**: 사용자 보고 — "메뉴에서 폴더를 열고 메뉴가 닫히면 그 폴더도 감춰져야 하는데 그대로 남아 있어서 엄청 불편해."

**처리**: `src/renderer.ts` 의 `onPanelHide` 가 `armOpenAnimation()` 만 부르고 폴더를 닫지 않았다.
패널 창은 `hide()` 되지 않고 **투명해질 뿐**이라(`windows/panel.ts` 의 깜빡임 대책) 오버레이 DOM 이 그대로 살아남는다.
→ `closeFolder()` 를 함께 호출.

**결과**: 사용자 확인 완료 ("폴더 문제는 해결이 되었어").

### 1-3. 탐색기에서 끌어다 놓기로 등록

**배경/요구**: 사용자 요청 — "메뉴 위젯이 나오고 난 다음에 드래그 앤 드롭으로 등록".
`docs/DIRECTION.md` 2단계 항목("드래그&드롭으로 항목 추가")이기도 하다.

**처리**: 신규 `src/ui/drop.ts` + 4파일 수정.
- `CH.GRID_ADD_FILES` 채널 신설 — 셸 확장의 `TOGGLE`(토글)과 달리 **언제나 추가**
- `preload.ts` 에 `pathForFile()` 노출 — Electron 32+ 에서 `File.path` 가 제거돼
  `webUtils.getPathForFile()` 을 **preload 에서만** 부를 수 있다
- `document` 에 `dragover`/`drop` 리스너. `preventDefault()` 를 빠뜨리면 브라우저가
  파일로 페이지를 이동시켜 그리드가 통째로 날아간다
- `dragenter`/`dragleave` 는 자식 경계마다 쌍으로 떠서 **깊이 카운터**로 강조를 관리

**결과**: 동작 확인. 사용자 요청으로 삽입 위치를 **맨 앞 → 맨 뒤**로 변경(1-5 참조).

### 1-4. 드래그하는 동안만 패널을 유지 (마우스 훅 추가)

**배경/요구**: 1-3 직후 사용자가 "끄는 동안 메뉴가 사라져" 라고 보고.
탐색기의 파일을 **누르는 순간**이 곧 패널의 포커스 상실이라 끌기 시작하자마자 패널이 닫혔다.

중간에 혼선이 있었다 — 사용자가 "안 닫히던데?" 라고 했고 나는 그 실측을 근거로
"포커스 문제는 실제로는 안 생긴다" 고 판단을 뒤집었다. 실제로는 사용자가 이전에
`BM_NO_BLUR_CLOSE=1` 로 띄운 개발 환경이었고, 배포본에서는 항상 켜지는 값이다.
검증용으로 그 값을 끄고 띄우자 사용자가 즉시 지적했다 — **"계속 안 없어지면 어떡해."**

**처리**: `native/hotkey` 프로세스에 `WH_MOUSE_LL` 저수준 마우스 훅 추가.
왼쪽 버튼 down/up 만 파이프로 보낸다(`MOUSE\tDOWN` / `MOUSE\tUP`). 좌표·다른 버튼은 보내지 않는다.

`windows/panel.ts` 의 blur 핸들러:
- 버튼이 **눌린 채** blur → 닫지 않고 **보류**(`blurDeferred`)
- 버튼을 뗄 때 커서가 패널 **위** → 드롭이다. 유지하고 **`win.focus()` 로 포커스 회복**
- 커서가 패널 **밖** → 원래 blur 가 하려던 대로 `hidePanel()`

> ⚠️ `win.focus()` 가 핵심이다. 빠뜨리면 이미 blur 된 상태라 다음에 밖을 클릭해도
> blur 가 다시 오지 않아 **영영 안 닫힌다** — 사용자가 지적한 그 증상이 그대로 재현된다.

**결과**: 사용자 확인 완료.

### 1-5. Ctrl+클릭 다중 선택 삭제

**배경/요구**: 사용자 요청 — "Ctrl 키를 누른 상태에서 클릭하면 프로그램이 실행되는 게 아니라 다중 선택".

**처리**: `src/ui/grid.ts` 에 `selected: Set<string>` + `bm-selected` 클래스.
- Ctrl+클릭 → 실행/폴더열기 대신 선택 토글 (앱·폴더 모두)
- 선택된 항목 우클릭 + 선택 2개 이상 → 다중 삭제 메뉴 하나만
- 선택 밖 우클릭 → 선택 해제 후 기존 단일 메뉴 (탐색기 관례)
- Esc → 선택이 있으면 **선택만** 해제 (폴더·패널 안 닫음)
- 패널 닫힘·재렌더·폴더 열기/닫기 → 선택 해제

`main.ts` 는 `removeEntry` 를 `spliceOut` + `removeEntries` 로 분리.
다중 삭제는 **매번 다시 찾아** 뺀다 — 앞 항목을 빼면 뒤 인덱스가 밀리고,
폴더와 그 자식이 함께 선택돼도 안전하다. 저장·재렌더는 마지막에 한 번.

**결과**: 사용자 확인 완료 ("정상 작동하는 것 같아").

### 1-6. 설치본 재배포와 설정 복구 사고

**배경/요구**: 사용자 요청 — "이제 인스톨 파일 만들어도 될 것 같아."

**처리**: 설치 전에 설정·셸 확장을 `%LOCALAPPDATA%\BluemingMenu-backup\2026-09-02\` 로 백업.
`npm run dist` → `dist\Blueming Menu Setup 0.1.0.exe` (95.8MB) 생성.

사용자가 설치한 뒤 보고 — **"내가 구성해 놓은 게 싹 다 없어졌어."**

원인 규명 결과 두 가지가 겹쳤다:
1. NSIS 가 이전 버전을 지우며 설치 폴더를 통째로 비웠다 → 설정 파일 소멸
2. **설치 위치가 바뀌었다** — 이전 `%LOCALAPPDATA%\Programs\BluemingMenu` → 이번 `C:\Program Files\BluemingMenu`
   `store.ts` 의 `configDir()` 이 시스템 위치를 감지해 설정을 `%APPDATA%\Blueming Menu` 로 보냈고,
   그 위치에는 설정이 없으니 **최초 임포트가 다시 돌아 184개**가 들어왔다

**복구**:
- 앱 종료 → 재임포트본을 `blueming-menu.config.reimported-2026-09-02.json` 으로 보관 → 백업본(25개·폴더 7개) 복원
- 셸 확장을 `Program Files` 아래에 직접 등록 시도 → **0x80070005 액세스 거부**
  (등록 과정이 그 폴더에 `microsoft.system.package.metadata` 를 만들려 한다)
  → `%LOCALAPPDATA%\BluemingMenu\shell-ext` 로 복사 후 등록 성공
- 앱 실행이 안 됐다 → 원인은 이 셸의 `ELECTRON_RUN_AS_NODE=1` (§4 참조)
- 탐색기 재시작 → 파이프 질의 `ADDED` 응답 확인

**결과**: 사용자 확인 완료 ("이제 정상으로 돌아왔어").

## 3. 시행착오

- **잘못된 가정**: 사용자의 "안 닫히던데?" 를 근거로 "드래그 중에는 blur 가 안 온다" 고 판단을 뒤집었다.
  - **발견 경위**: `BM_NO_BLUR_CLOSE=1` 없이 띄우자 로그에 `blur 닫기 on` + `hidePanel — 투명화` 가 그대로 찍혔다.
    사용자의 관찰은 그 값을 끈 개발 환경에서 나온 것이었다.
  - **복구**: 원래 분석(포커스 상실이 원인)으로 되돌리고 마우스 훅으로 해결.
  - **교훈 한 줄**: **사용자 실측을 받아들이되 실행 환경(환경변수·설정)이 같은지 먼저 맞춰라.**

- **잘못된 가정**: 검증하려고 `BM_NO_BLUR_CLOSE=1` 로 띄운 상태를 그대로 두고 사용자에게 확인을 요청했다.
  - **발견 경위**: 사용자가 즉시 지적 — "계속 안 없어지면 어떡해."
  - **복구**: 즉시 정상 설정으로 되돌리고 마우스 훅 구현.
  - **교훈 한 줄**: **검증용으로 안전장치를 끈 상태를 사용자에게 넘기지 마라.** 격리 실험이면 실험이라고 못박고 즉시 되돌린다.

- **잘못된 가정**: 재설치 시 설치 위치가 이전과 같을 것이라고 봤다.
  - **발견 경위**: 복원하려는데 `%LOCALAPPDATA%\Programs\BluemingMenu\BluemingMenu.exe` 가 없었다.
    실행 중인 프로세스 경로를 보니 `C:\Program Files\BluemingMenu` 였다.
  - **복구**: `store.ts` `configDir()` 의 분기를 따라 `%APPDATA%` 쪽에서 설정을 찾아 복원.
  - **교훈 한 줄**: **설치 경로를 넘겨짚지 말고 실행 중인 프로세스의 `Path` 에서 읽어라.**

- **잘못된 가정**: 백업만 떠 두면 재설치가 안전할 것이라고 봤다.
  - **발견 경위**: 백업은 유효했으나, 설치 후 앱이 자동 실행되며 **재임포트 184개**가 이미 저장된 뒤였다.
  - **복구**: 앱을 먼저 끄고 복원. 재임포트본은 지우지 않고 별도 이름으로 보관.
  - **교훈 한 줄**: **복원 전에 앱을 반드시 끈다.** 켜진 채 덮어쓰면 메모리의 설정이 다시 저장돼 백업을 덮는다.

## 4. 발견한 코드베이스 함정

### 4-1. ⚠️ 이 셸에는 `ELECTRON_RUN_AS_NODE=1` 이 걸려 있다

VS Code 안에서 도는 Claude Code 셸의 환경변수다. 여기서 패키징된 `BluemingMenu.exe` 를 실행하면
**Electron 이 아니라 Node 로 돌다가 조용히 끝난다.**

- 창도, 로그도, 크래시 덤프도 없다. `exit 0` 이라 성공처럼 보인다
- Crashpad 리포트·`%LOCALAPPDATA%\CrashDumps`·Application 이벤트 로그 **전부 비어 있다**
- **단서**: `--enable-logging=stderr` 를 주면 `bad option: --enable-logging=stderr` 가 찍힌다.
  이건 **Node 의** 오류 메시지다. Electron 이면 정상 인식하는 플래그다
- **해법**: `unset ELECTRON_RUN_AS_NODE` 후 실행. 또는 PowerShell 쪽에서 실행
- `npm start` 개발 실행은 electron-vite 가 자체 처리하므로 영향받지 않는다

이 함정 때문에 "설치본이 실행되지 않는다" 로 20분을 썼다.

### 4-2. ⚠️ NSIS 재설치는 설치 폴더를 통째로 비운다

이전 버전 제거 단계가 `RMDir /r` 로 밀기 때문에 설치 폴더 안에 둔 것은 전부 사라진다.
이 프로젝트는 **설정 파일이 포터블 방식으로 설치 폴더 안에 있어서**(사용자 결정 2026-08-18) 직격이다.

설정이 없으면 앱은 `imported: false` 로 읽고 **최초 임포트를 다시 돌린다.**
사용자 눈에는 "구성해 놓은 게 싹 날아가고 전부 다시 나타남" 으로 보인다.

설치 위치별 설정 파일 위치가 다르다 (`src/store.ts` `configDir()`):

| 설치 위치 | 설정 파일 | 재설치 |
|---|---|---|
| 사용자 폴더 (per-user) | `<설치루트>\blueming-menu.config.json` | **삭제된다** |
| `Program Files` | `%APPDATA%\Blueming Menu\blueming-menu.config.json` | 설치 폴더 밖이라 **살아남는다** |

2026-09-02 현재 설치본은 `C:\Program Files\BluemingMenu` 이므로 설정은 `%APPDATA%` 쪽이다.
다만 **이번 재설치처럼 설치 위치 자체가 바뀌면** 옛 위치의 설정이 고아가 되고 새 위치는 비어 있어 재임포트가 돈다.

**절차**: 재설치 전 설정 백업 → 설치 → **앱 종료** → 복원 → 앱 실행.

### 4-3. ⚠️ `Program Files` 아래의 셸 확장은 직접 등록할 수 없다

`Add-AppxPackage -Register ... -ExternalLocation "C:\Program Files\BluemingMenu\resources\shell-ext"` 는
**0x80070005 (액세스 거부)** 로 실패한다.

```
오류 0x5: ...\shell-ext\microsoft.system.package.metadata 패키지 메타데이터 디렉터리를 만들지 못했습니다.
```

등록 과정이 대상 폴더에 메타데이터 디렉터리를 **쓰려고** 하는데 `Program Files` 는 관리자만 쓸 수 있다.
관리자로 등록해도 per-user 등록이라 의미가 어긋난다.

**해법**: `resources\shell-ext` 를 `%LOCALAPPDATA%\BluemingMenu\shell-ext` 로 복사한 뒤 그쪽을 등록한다.
설치 폴더 안(`<설치루트>\shell-ext`)에 두면 4-2 때문에 재설치마다 지워지므로 그것도 안 된다.

### 4-4. ⚠️ `scripts/setup-installed.ps1` 은 이제 그대로 쓸 수 없다

두 가지 전제가 깨졌다.

1. **per-user 설치를 전제**로 `Find-InstallRoot` 가 짜여 있다. `Program Files` 설치도 찾긴 하지만
   그 뒤 셸 확장을 `<설치루트>\shell-ext` 에 복사해 등록하려다 4-3 으로 실패한다
2. **설정 이전 단계가 개발용 설정을 실사용 위에 덮어쓴다.** 개발 루트의 설정(폴더 0개, 68개 항목)을
   설치본으로 복사하는 것이 원래 목적이었는데, 실사용 배치(25개·폴더 7개)가 이미 있는 지금은 파괴적이다.
   `-Force` 없이는 건너뛰긴 하지만 의도가 어긋난 스크립트를 그대로 두는 것 자체가 위험하다

### 4-5. 셸 확장 등록은 실패해도 조용하다

`Get-AppxPackage` 의 `Status` 는 경로가 사라져도 **`Ok`** 로 남는다.
판별 기준은 **`InstallLocation` 이 비어 있는가** 하나다. 비어 있으면 깨진 것이다.

`HKCU\Software\Classes\PackagedCom\Package\<패키지>` 에는 `REG_DWORD` 값 하나만 있고
클래스 정보는 레지스트리가 아니라 상태 저장소(StateRepository)에 있다.
**레지스트리를 뒤져서는 COM 등록 여부를 알 수 없다.** `explorer.exe` 의 로드된 모듈 목록을 보는 편이 빠르다.

### 4-6. 폴더 이름을 바꿔도 셸 확장은 한동안 멀쩡히 동작한다

탐색기가 이미 메모리에 올린 DLL 을 계속 물고 있기 때문이다.
**다음 재부팅(또는 탐색기 재시작)까지 증상이 안 나타난다.**
그 사이에 윈도우 업데이트가 끼면 원인이 업데이트로 오인된다 — 이번이 정확히 그 사례다.

- > "등록할 때 맨 앞에 들어가는데, 맨 뒤에 들어가게 해 줘. 이거 불편해."
  — 끌어다 놓기 등록 위치. 2026-08-18 에 "맨 뒤는 안 보여서 등록이 안 된 것 같다" 는 이유로
  맨 앞으로 정했던 결정을 **끌어다 놓기에 한해** 뒤집은 것이다.
  셸 확장 등록(`toggleByLnkPath`)은 여전히 맨 앞이다. 적용 범위를 혼동하지 말 것.

  — blur 닫기는 **끄는 것이 아니라 조건부로 미루는 것**이라는 요구. 마우스 훅 구현의 직접 근거.

- > "Ctrl 키를 누른 상태에서 클릭하면 프로그램이 실행되는 게 아니라, 다중 선택이 되게끔"
