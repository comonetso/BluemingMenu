## 1. 작업 흐름

### 1-1. 초기화 시점 판단 — 사용자 질문에 대한 답

**배경/요구**: 사용자가 "프로젝트 초기화를 개발 진행 후에 할지, 처음부터 할지" 를 물었다.

**처리**: 처음에 해야 한다고 답하고 그대로 진행. 근거는 두 가지였고 **둘 다 세션 중 실증됐다.**

1. Electron 은 `package.json` 의 `main` 과 `electron` 바이너리 없이는 창 하나 못 띄운다.
   "개발하다가 초기화" 는 웹 라이브러리에서나 성립한다
2. `.gitignore` 를 `npm install` **전에** 깔아야 `node_modules` 가 커밋에 안 섞인다

**결과**: 순서대로 `git init` → `.gitignore` → 스캐폴딩 → `npm install` → 첫 커밋. 혼입 0건.

### 1-2. 다국어 — 세션 중 추가된 요구

**배경/요구**: 작업 도중 사용자가 "영어하고 한국어 다국어 버전으로 만들 거야" 라고 알림.
`DIRECTION.md` 1~8장 어디에도 다국어 언급이 없었다.

**처리**: 1단계 착수 **전에** 확정받았다. i18n 은 나중에 붙이면 문자열이 코드 곳곳에 박혀 있어
걷어내는 비용이 훨씬 크다. 3가지를 물어 확정 → `DIRECTION.md` 3.6 신설.

**결과**: `[i18n] OS=ko → ko | Blueming Menu 에 등록` 로그로 동작 확인.

### 1-3. 아이콘 — GPT 이미지에서 SVG 로 전환

**배경/요구**: 사용자가 "니가 이미지를 못만드니까 gpt에서 생성을 맡길 것" 이라며 프롬프트를 요청.
프롬프트 3안을 만들어 드렸고, 사용자가 GPT 결과물을 가져왔으나 만족하지 못했다.

**처리**: 이어서 "코덱스에게 아이콘 뽑아 달라고 할까" 물으셨을 때 **전제를 정정**했다 —
Codex 도 이미지 생성을 못 하고, 무엇보다 **SVG 는 코드라 내가 만들 수 있다.**
아이콘 용도로는 벡터가 정석이라는 근거(16px 축소 · 색 수정 · 투명 배경)를 제시하고 방향을 다시 받았다.

**결과**: SVG 5안 제작 → 미리보기 HTML 로 실제 축소 크기 비교 → D안 채택.

### 1-4. 트레이 상주 — 세션 중 추가된 요구

**배경/요구**: "dev로 띄우는데 트레이에 아이콘이 항상 나와있어야 하니까" — `DIRECTION.md` 에 없던 항목.

**처리**: `Tray` 추가 + `window-all-closed` 를 비움 + 메뉴 문구를 i18n 리소스로 분리.
`DIRECTION.md` 4장 1단계에 반영.

**결과**: 사용자 확인 "괜춘". 종료 후 잔여 프로세스 0.

## 3. 시행착오

### 3-1. `create-electron-app` 이 빈 디렉토리를 요구한다
- **잘못된 가정**: 기존 `docs/` 가 있어도 현재 디렉토리에 스캐폴딩되겠거니 했다
- **발견 경위**: 실행 → `FAILED: The specified path ... is not empty`
- **복구**: 하위 `_scaffold/` 에 생성 → 파일을 루트로 `mv` → `_scaffold` 제거.
  `node_modules` 도 같이 `mv` 해서 `npm install` 을 두 번 돌리지 않았다
- **교훈**: 이 사례가 "초기화를 처음에 해야 한다"는 근거를 하나 더 실증했다.
  개발을 진행한 뒤였다면 이 우회가 훨씬 지저분했다

### 3-2. i18next 설치가 ERESOLVE 로 막힘
- **잘못된 가정**: 템플릿이 깔아준 TypeScript 가 최신일 것이라 여기고 그냥 `npm i i18next` 실행
- **발견 경위**: `peerOptional typescript@"^5 || ^6 || ^7" from i18next@26.3.6` / `Found: typescript@4.5.5`
- **복구**: `typescript@^5` 설치 → 5.9.3. 재시도 성공
- **교훈**: **Forge 템플릿의 기본 의존성 버전은 낡았다.** 2021년 릴리스가 들어 있었다.
  첫날에 밟은 게 다행이다 — 코드를 쌓은 뒤였으면 타입 에러를 한꺼번에 맞았다

### 3-3. D안에서 꽃잎 하단과 상승 호가 겹침
- **잘못된 가정**: `scale(0.88)` 후 꽃잎 하단이 충분히 올라갈 것이라 봤다
- **발견 경위**: 렌더 전에 좌표 검산 — 꽃잎 하단 y≈196.5, 호 상단 y≈192 → 겹침
- **복구**: 호를 `M 70 214 Q 128 190 186 214` → `M 70 226 Q 128 202 186 226`
- **교훈**: **SVG 는 렌더 전에 계산으로 검증된다.** 이미지 생성이었으면 눈으로 보고 재생성 요청뿐이다

## 4. 발견한 코드베이스 함정

**(1) 프로젝트 경로에 공백이 3개** — `Etc Project` · `Electron Project` · `Blueming Menu`
`DIRECTION.md` 7장이 경고한 최대 리스크였다. **결론: Forge + Vite 는 정상 동작한다.**
`npm start`·`npm run package` 모두 통과. 다만 셸 명령에서 인용을 빠뜨리면 여전히 깨진다.

**(2) `MAIN_WINDOW_VITE_*` 상수의 유래**
`forge.config.ts` 의 `renderer: [{ name: 'main_window' }]` 가
`MAIN_WINDOW_VITE_DEV_SERVER_URL` / `MAIN_WINDOW_VITE_NAME` 두 전역 상수를 만든다.
타입 선언은 `forge.env.d.ts` 의 `/// <reference ... forge-vite-env />` 한 줄에서 온다.
**renderer 이름을 바꾸면 상수 이름도 바뀌고** `main.ts` 의 dev/prod 분기가 깨진다.
세 파일을 다 읽어야 보이는 연결이라 `CLAUDE.md` 에 박아뒀다.

**(3) `Tray` 객체는 GC 되면 아이콘이 사라진다**
지역 변수로 잡으면 잠시 뒤 트레이에서 사라진다. **모듈 스코프에 붙들어야 한다.**
`src/main.ts` 의 `let tray: Tray | null = null` 이 그 이유다.

**(4) 트레이 아이콘은 `.ico` 를 줘야 한다**
이 PC 는 DPI 스케일이 걸려 있어(150% 추정) 단일 PNG 를 주면 뭉갠다.
`.ico` 는 16~256px 을 모두 담고 있어 Windows 가 알맞은 해상도를 고른다.

**(5) `app.getLocale()` 은 `ready` 이후에야 정확하다**
그래서 i18n 초기화를 `app.on('ready')` 안에서 한다.

**(6) `app.getAppPath()` 는 개발 중 프로젝트 루트를 가리킨다** — 실측 확인.
`[tray] 준비 완료 — F:\...\Blueming Menu\assets\icons\icon.ico`
덕분에 dev/prod 경로 분기 없이 `path.join(app.getAppPath(), 'assets', ...)` 하나로 된다.

**(7) 아이콘은 해상도마다 SVG 에서 개별 렌더해야 한다**
큰 PNG 를 축소하면 작은 크기가 뭉갠다. `scripts/build-icon.mjs` 가 7종을 각각 렌더한다.
`sharp` 는 `<use href>` (SVG2 문법) 를 정상 처리한다 — 실측 확인.

**(8) Windows 에서 방금 `cd` 한 디렉토리는 `rmdir` 이 거부된다**
`_scaffold` 제거 시 `Device or resource busy`. 셸이 물고 있어서다. 잠시 뒤 재시도하면 된다.

**(9) `TaskStop` 은 `electron.exe` 자식 프로세스를 죽이지 않는다**
`npm start` 를 백그라운드로 돌리고 중지하면 npm/forge 만 죽고 `electron.exe` 가 10개 남았다.
GPU 캐시 에러(`Unable to move the cache`)의 원인이기도 하다.
정리: `taskkill //F //IM electron.exe //T`. **단 다른 Electron 개발 프로젝트가 돌고 있지 않은지
먼저 확인해야 한다** (실행 경로로 판별 가능: `Get-CimInstance Win32_Process`).

## 5. 사용자 핵심 발언

- > "어투는 존대말로 되어 있을텐데.. 왜 반말?"

  전역 `CLAUDE.md` 와 `korean-rule` 스킬을 실측했으나 **어디에도 어투 규정이 없었다.**
  사용자는 있다고 기억하지만 실제로는 없다. → 메모리 `honorific-tone` 으로 빈칸을 메웠다.

- > "니가 이미지를 못만드니까, gpt에서 생성을 맡길껀데"

  **절반만 맞다.** 래스터(PNG/JPG)는 못 만들지만 **SVG 는 코드라 만들 수 있다.**
  이 정정이 세션의 방향을 바꿨다 — 프롬프트 대필에서 실제 제작으로.
  같은 오해가 재발할 수 있어 메모리로 남겼다.

- > "D로 가고 향후에 실적용해보고 바꾸면되지..ㅋㅋ"

  **완벽주의로 붙잡지 말라는 신호다.** 선택지를 계속 다듬어 제시하기보다
  일단 굴려보게 하는 편이 이 사용자에게 맞는다. 메모리로 남겼다.

- > "트레이에 아이콘이 항상나와있어야하니까, 일단 뛰워봐,, 내가 확인할께"

  문서에 없던 요구. 즉시 반영하고 `DIRECTION.md` 에 기록했다.
